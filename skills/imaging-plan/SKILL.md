# 卫星成图编成

把一个"要覆盖多大面积、多清晰、多久能拿到"的需求，反推成一份星座编成方案。

## 什么时候用

- "覆盖 XX 90% 需要几颗星"
- "给定 3 颗星，能覆盖多少"
- "达到 24 小时重访需要几颗星"
- "给我排一个成图计划 / 出个方案"

## 什么时候不要用

| 场景 | 去哪 |
| --- | --- |
| 只问"明天有哪些过境""哪次过境最合适" | `pass-planning` |
| 问 TLE 新不新鲜、同步失败 | `tle-health` |
| 问卫星参数、在轨位置 | `ephemeris-query` |
| 目标范围在浙江省以外 | 直接拒绝，本版本只支持浙江 |
| 问云量、天气、成像质量 | 本 skill 不涉及 |

## 流程

1. **确定任务模式**（必需）——四选一：
   `min_sats_for_coverage` 最少星达覆盖率 / `min_sats_for_revisit` 最少星达重访 /
   `max_coverage_for_n` 给定 N 颗最大覆盖 / `min_wait_for_n` 给定 N 颗最小等待。
2. **确定目标范围**（必需）——先调 `mcp__rs-service__list_aoi`（默认 `level=city`）取可选范围；
   提问时 `options` 只能来自返回的 `items`（当前为浙江 11 个地级市），另外允许用户自定义 adcode、名称或 `POLYGON` WKT。
   浙江省外（北京、上海等）**不得作为选项**；用户主动提出时直接拒绝并说明本版本只支持浙江。
3. **确定传感器类型**（必需）——`optical` / `sar` / `hyperspectral`，可多选。默认三类全开。
   微波星（HY-2 系列等）是非成像载荷，不在枚举里。
4. **确定最大分辨率**（必需，单位米）——数值越小越清晰。注意这是"不差于"。
5. **确定目标覆盖率**（必需，百分比）。
6. **调用 `mcp__rs-service__plan_coverage`**，拿 JSON。
7. **渲染报告**：把 JSON 交给 `scripts/render.py`，生成 HTML，给出绝对路径。

## 参数不全怎么办

工具不会猜。它返回：

```json
{"ok": false, "error": "missing_params",
 "missing": ["max_resolution_m"],
 "schema": {"max_resolution_m": {"type": "number", "unit": "m", ...}}}
```

收到这个错误时：

- **有 `ask_user_question` 工具就用它**，按 `schema` 逐项追问；`options` 字段直接作为选项；
  `aoi` 的选项必须来自 `list_aoi` 的返回，不要凭常识补充省外城市；
- **没有就文本追问**，一次列全，不要一项一项问。

无论哪种，都**不要替用户假设默认值**（除了 `sensor_types` 默认三类全开、`hours` 默认 72）。

## 输出口径（必须随结果一起说）

- 覆盖率、重访间隔都是**估算值**，带 `estimate` 含义；不得说"精确覆盖""保证重访"。
- 过境时间误差 ±1 分钟，足迹边缘 ±2–5 km。
- 重访间隔默认看 **P95**（保证性），平均值会被密集过境拉好看。
- 报告里必须保留 `algo_version` / `parser_version` / 网格间距，便于复现。
